# 桂桥分站调拨期末盘点台账

发站收站分开交簿，按交接日还原工具去向，核对各站、在途与全站有效资产。

桂桥社区工具共享站向东风、南苑、湖畔三个分站调拨工具，发站与收站分别登记调出单和实收单。 值班员分别整理发站调出簿与分站实收簿，按单号配对两站记录。站务协调员按月核对各站存量、在途工具与待核单据，复核后将台账交给居委会资产管理员。

- 发站与分站各记一本交簿，月底对账时调出与实收对不上，查不到工具到底在谁手里。
- 实收单先到、调出单晚到时，补录重算容易把同一笔调拨重复计入。
- 在途工具两边都不入账，月末全站资产莫名变少；单号对上但内容不符时更难定位。

## 业务模块

| 模块 | 用途 |
|---|---|
| 值班总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 调拨单据 | 下载「桂桥分站调拨交簿_20261121.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 期末盘点 | 选择批次和参数并提交后台计算，可从运行列表追踪状态。 |
| 快照与月度勾稽 | 查看业务指标、证据表和解释，通过来源链接回查数据。 |
| 台账复核 | 查看待处理或已完成记录。复核主管可提交台账复核及依据。 |
| 盘点报告交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 演示流程

1. 11 月 21 日 09:10，值班员将桂桥调出簿与各分站实收簿整理为「桂桥分站调拨交簿_20261121.csv」。
2. 在「调拨单据」导入 CSV，核对重复上传的 DB-0901 调出记录只回放一次。
3. 在「期末盘点」设定 9 月 1 日至 10 月 31 日，核对 10 月末全站 5 件：桂桥 1、东风 2、南苑 1，GQ-03 在途 1 件仍计入全站。
4. 将截止日改为 11 月 20 日重跑，核对期末全站 4 件＝各站 3 件＋在途 1 件（GQ-04），GQ-05 已退役。
5. 在「快照与月度勾稽」查看待核单据：DB-1103 去向不符（GQ-01 仍记东风分站）、DB-1105 实收单晚到（GQ-06 暂未入账）。
6. 补录调出簿晚到的两行，导入新批次重跑，GQ-06 按 11 月 16 日接收、17 日调出、18 日实收补算，全站变 5 件且不重复计入：

   ```csv
   slip_no,asset_id,asset_name,handover_date,sequence,event_type,from_station,to_station
   RK-006,GQ-06,棘轮扳手套装,2026-11-16,1,intake,,桂桥
   DB-1105,GQ-06,,2026-11-17,1,dispatch,桂桥,湖畔分站
   ```

7. 在「台账复核」登记 DB-1103 的核实结论，在「盘点报告交付」导出已复核的勾稽结果。

## 计算口径

- 单据按「类型＋编号＋工具」去重，内容一致只回放一次；内容冲突或同工具同日顺序号重复时提示修正，补录后重跑不重复计入。
- 调出单按交接日使工具离开发站、进入在途；实收单按交接日使工具进入收站。在途工具仍计入全站有效资产。
- 只有实收单、调出单未到的记录先挂待核，不计入任何环节；调出单补录配齐后，按实际交接日补算调出与实收。
- 单号对上但工具或去向不符时，涉事单据不生效，工具按调拨前状态记账并标待核；同单其余工具照常计算。实收日早于调出日的配对同样挂待核。
- 截止日含当日全部单据。期初取首日之前的状态，逐月展示自然月末盘点，截止日早于当月末时另列该日日终快照；整段期末取最后一张快照。待核单据按截止日过滤，晚于截止日的不计入本期。
- 全站有效资产＝各站存量合计＋在途件数；全站期末＝期初＋接收−退役。分站、在途与全站分层勾稽：站点流入＝接收＋实收调入、流出＝调出，在途流入＝调出、流出＝实收，全站仅接收流入、退役流出，差额为 0 方可提交复核。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | PostgreSQL 16 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
